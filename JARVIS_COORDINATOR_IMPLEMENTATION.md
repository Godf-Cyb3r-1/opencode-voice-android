# Jarvis primary coordinator — first implementation

## Intent

Jarvis owns the conversation. OpenCode is delegated execution infrastructure.
Spoken content is generated by a separately configured fast dialogue model, not
static greeting scripts, status phrases, or raw OpenCode reasoning.

## Runtime changes

- `JarvisCoordinator` keeps a separate dialogue OpenCode session and worker OpenCode session.
- The conversational model may be selected via **Voice Studio → Jarvis fast dialogue model** using an already-enabled OpenCode provider/model ID, e.g. a locally configured small non-thinking model.
- Activation creates a dynamic model-composed opening. The model returns structured `say` and `delegate` fields for user turns, deciding whether to hold conversation or initiate delegated execution.
- Subagent execution can outlive a spoken conversational answer. Work stages are visible in the HUD. A long-running task prompts a model-generated progress update; task completion generates another contextual update including a next step.
- New user input invalidates stale dialogue/speech responses without stopping the task. The Android button can interrupt current playback.
- Pocket TTS and Moonshine STT remain the I/O layer. STT is suppressed during Pocket TTS playback to avoid recognizing Jarvis's own voice.

## No hardcoded voice scripts

Java prompt strings describe *situations* and voice character; user-facing speech
is generated by the dialogue model. Voice Studio's fixed speech preview and
speed confirmation have been removed.

## Important unfinished work

**This does not yet bundle a standalone small local LLM.** The configured model
must already be usable through OpenCode. To achieve low-latency on-device
conversation, install/configure a compatible local provider and choose its fast
model in Voice Studio; the app does not install Qwen/llama.cpp automatically.

**Not full-duplex yet.** Tap interruption is wired, but true spoken barge-in
requires acoustic echo cancellation and continuous mic capture during TTS.

**Not yet concurrent TTS synthesis.** Pocket TTS currently queues synthesis and
playback on one inference worker. Sentence prefetch and a separate ordered audio
playback queue are the next voice-engine step.

**Not fully preemptive scheduling.** The dialogue session serializes requests;
a slow current prompt could still delay a later prompt. Reliable cancellation
and model benchmarks remain necessary.

**Not verified on the device.** GitHub Actions validates compilation and APK
packaging, not emotion, recognition accuracy, realtime latency, or background
microphone permissions.

## Suggested testing

1. Select an already configured fast non-thinking model in Voice Studio.
2. Activate Jarvis. Its spoken greeting must be fresh, not a fixed text.
3. Say hello, then make a complex work request. Verify Jarvis speaks and
   the separate worker executes; not every greeting should create work.
4. During execution, speak again after the response. Confirm the work
   continues without waiting for another worker completion.
5. Check progress announcements, completion summary and next-step suggestion.
6. Tap during speech. It should stop audible playback without killing work.
7. Verify that no reasoning, tool output or synthesized prompts are spoken.
